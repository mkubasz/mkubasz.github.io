What temperature does to a softmax

You ask a coding agent: “Please add a green button to my new platform.” What does it write?

A plain button? A button in a floating window? A button shaped like a spaceship? The answer is generated one token at a time, and at each step a different token can be picked. Temperature changes how often sampling picks something other than the top-scoring token. This post follows one request through that choice.

1. What happens after you ask for a green button?

You want one green Save button that fits the page and leaves everything else alone. The model can continue this request in many ways. Some of them are useful variations. Some are not what you asked for.

It may add a hover effect. It may put the button in a floating window. It may start drawing a spaceship. The question for this post: how much variation does this task need?

In an API that supports it, you can set temperature alongside the prompt:

{
  "model": "your-model",
  "messages": [{
    "role": "user",
    "content": "Add a green Save button to this page."
  }],
  "temperature": 0.2
}

At a low temperature, sampling picks the highest-scoring tokens more often. At a high temperature, lower-scoring tokens are picked more often. For a small code change you usually want the first. For new conversation ideas some variation helps.

This request is an illustration. Many coding agents do not expose temperature, and some reasoning models accept only the default value. Ranges differ too: some APIs stop at 1. Temperature changes how tokens are sampled; it does not add knowledge or make an answer correct. See the Hugging Face temperature documentation.

The answer is not generated as a finished button in one step. It is generated one token at a time.

2. The answer grows one token at a time

The model writes in pieces called tokens. A token can be a word, part of a word, or a punctuation mark. Say the model has started writing HTML and the text so far is <. The next token could be button, a, or canvas.

For every token in its vocabulary, the model computes a logit: an unnormalized score for that token as the next one. A higher logit means the model prefers that token. A logit of 3 does not mean 3%, and a high logit does not mean the token is correct.

Logits are not probabilities yet. Softmax turns them into probabilities. A separate step, sampling, then draws one token, weighted by those probabilities. Temperature changes the probabilities before that draw.

All logits and continuations below are invented for this post. A real model computes a logit for every token in a vocabulary of tens of thousands of tokens; the percentages here belong to these small examples.

3. Softmax turns logits into probabilities

The probabilities of all possible next tokens add up to 100%. Logits can be negative or larger than one, so they cannot be used as probabilities directly. Softmax first turns each logit into a positive weight, then divides each weight by the sum of all weights.

The formula, with temperature included:

Why the exponential, exp? It turns every logit into a positive weight, a negative logit too. A logit that is higher by 1 gets a weight about 2.7 times larger. Why the sum underneath? Without it the weights would not add up to 100%, so they would not be probabilities.

Why divide by temperature? It scales the differences between logits before the exponential. At $T = 1$ nothing changes: this is the model’s own distribution and the default in many APIs. Below 1 the differences grow and the top token gets more probability. Above 1 they shrink and probability spreads to the other tokens.

For a conversation, an unusual opening can be a good exercise. For a button, an unusual HTML element means extra work. For an email, an invented discount is a promise nobody approved. Whether variation helps depends on the task.

Temperature scales the gap between the top two tokens

Take the two tokens with the highest logits. After dividing by $T$, their gap is the original gap divided by $T$. At low temperature the gap is larger, so the top token is picked more often. At high temperature the gap is smaller, so the second token is picked more often.

Temperature never changes the order of the tokens: dividing every logit by the same positive number keeps their order. It changes only how much probability each token gets.

5. Try it: move the temperature

Move the slider and watch the probabilities change. Keep the button task, or choose Draft an email in the task menu above. Which temperature would you give an agent that writes emails on your behalf?

As $T$ rises, the top token loses probability to the others. At a high temperature, sampling can still pick the top token. At a low positive temperature, it can still pick another one: in the button task at $T = 0.2$, a still has about 18%.

Temperature does not decide what the agent may do. If the task says “draft an email,” no draft authorizes sending it. If it says “tell Alex the invoice is ready,” a discount or an account upgrade is outside the task. The task and the agent’s tools set which actions are allowed; temperature does not.

The formula needs $T > 0$. Some APIs treat $T = 0$ separately and always pick the top token (greedy decoding).

6. Each picked token becomes input for the next one

A picked token becomes part of the text. The model computes the logits for the next token from the text including that token. So one unusual early token makes related tokens more likely next, even when the result moves away from the request.

The first pick is not the only problem. Once the model has written drawing code, that code is part of the input for every next token. The next lines fit the drawing and move further from “one green button.” The rest of the answer follows the early token, not the request.

The task description matters too. “Add a button” leaves many decisions open. “Add a native green Save button using the existing style; change nothing else” leaves fewer. Unrelated requests in the same prompt, such as animations, pop-ups or a redesign, add more decisions.

A longer prompt is not automatically worse. Relevant details help. Missing details, conflicting requests and unrelated material make the task harder. Prompt text and temperature act in different places: the text changes the logits, temperature changes how a token is sampled from them.

A longer prompt also does not mean every detail is used equally well. In Lost in the Middle, the position of the relevant information in a long input changed accuracy on question-answering and key-value retrieval tasks.

7. Set temperature per task

If you build agents on a model API, you choose a temperature for each call. An agent making a small code change and an agent writing conversation scenarios need different amounts of variation.

Temperature by task
Agent and roleTemperatureWhy
Coding agent
(implement a narrow specification)		LowerYou usually want a focused change that fits the existing code.
Email agent
(draft a message from supplied facts)		LowerFewer unexpected tokens. The facts and promises still need checking.
Writing agent
(offer wording alternatives)		ModerateA few different phrasings give you something useful to choose from.
Scenario agent
(prepare conversations)		Default or higherDifferent situations make practice less repetitive.

The same agent can need a different temperature for a different task. A coding agent asked for several design options benefits from more variation. An email agent asked for playful drafts can use a higher temperature too.

  • Write a clear task. Say what to create, which facts to use, and where the task ends.
  • Raise the temperature when you want alternatives. Generate a few results and keep the ones that fit the task.
  • Check before acting. A draft needs review before it becomes an email; code needs checking before it becomes a change people use. At a low temperature, sampling picks a wrong top-scoring token as reliably as a right one.

Ask for a spaceship when you want one. For one green button, write a clear task first; a low temperature helps only after that.
